Development environment

The headless suite uses Python's standard library, principally unittest, threading, queue, dataclasses, and mock injection. requirements-dev.txt is deliberately dependency-free. GUI construction additionally needs Tkinter; importing the GUI for fake-widget tests does not construct a Tk window. Refactored image display uses tk.PhotoImage and subsampling. Pillow belongs to the legacy display/captured package baseline, not this refactored display path.

The recorded Windows environment exists at ..\growtechwall-venv; this task confirmed its interpreter runs Python 3.11.9. That is a local development environment, not a portable dependency path or proof of the current Pi installation. The historical Pi capture records Python 3.11.2 on Debian 12/aarch64; see Pi environment.

requirements-pi.txt pins NumPy 2.2.6, Pillow 11.2.1, pyserial 3.5, OpenCV 4.11.0.86, Torch 2.7.0, torchvision 0.22.0 and Ultralytics 8.3.147. These are proposed direct dependencies derived from the capture. ARM wheel sources, resolved transitive versions and an independently reproduced installation are still missing. Do not install this file into the laptop test environment just to run mocks.

The refactored entry point accepts --simulate and --verbose; it does not expose configuration-file/port/model CLI overrides. Defaults live in config/settings.py. Hardware composition checks Linux, aarch64 and Raspberry Pi device-tree text before hardware provider imports. That guard establishes a platform category, not the identity or readiness of the deployed system.

Safe headless command

From PowerShell, using the already-existing local interpreter:

Set-Location '.\source code\Raspberry Pi\GUI\refactored'
& 'python' -B -m unittest discover -s tests -q

For another checkout/interpreter, use its corresponding path and the same working directory. -B suppresses bytecode writes. This is the repository's actual runner; the generic pytest example in root guidance is conditional and does not describe this standard-library suite.

Before running a later revision, inspect added/modified tests and provider construction. Do not import the legacy GUI or arm library. Source-level inspection can use ast.parse() or compile(source, filename, 'exec') without executing the code. A successful parse is syntax evidence, not runtime or physical evidence.

Optional laptop GUI inspection

After confirming Tk availability and simulation isolation, this is the software-only entry point:

Set-Location '.\source code\Raspberry Pi\GUI\refactored'
& 'python' -B app.py --simulate

The command syntax/provider selection was inspected in this task; a new interactive GUI session was not run. The July record includes operator-confirmed Windows simulation. Future inspection should record the commit/date/operator and expected/observed controls instead of relying on that older observation for changed widgets.

Mocks preserve selected command/event shapes, not real timing. Gantry movement is immediate; no switches or travel are sampled. Arm groups are recorded and workflow waits collapse in simulation. Mock vision supplies deterministic labels and no image path. Mock hydroponics uses fixed sensor values and dose-display timers, without actual ADC/RTC/acidity/EC control. These differences are intentional test accommodations, not replacement controller algorithms.

Extending the implementation

• Select one boundary and identify the evidence level it requires.

• Inspect source and capture synthetic/captured fixtures before changing behavior. Never fabricate a captured transcript from an encoder example.

• Keep pure conversion in domain/protocol/vision logic; keep resource opening behind explicit providers; pass events rather than widgets to workers.

• Use injected clocks/schedulers/transports for timing and failure cases. Include a meaningful acceptance condition, not merely a test duplicating the implementation.

• Run the relevant existing tests. Run the suite when shared lifecycle/state/protocol behavior changes, after rechecking isolation.

• Review protocol bytes, constants, pins, timing, model policy, reset behavior and startup path explicitly. Record intentional differences.

• Keep deployment and physical approval separate. No merge into main before the phase's required physical checks pass.

For comments alone, token/AST preservation is the main check. This pass adds no tests and makes no behavior fixes. See 08 for the comment comparison method.

Pi recovery and rollback references

The confirmed legacy operator procedure is manual startup after boot. Console tty1 auto-login is not GUI autostart. The following is reference-only here: executing it opens hardware and may reset/home controllers.

cd "/home/growtechwall/Desktop/IDP-Grow-Tech-Wall/Raspberry Pi/GUI"
source /home/growtechwall/venv-ultralytics/bin/activate
python3 GTW_GUIv2.py

Use the deployment manifest for SD/boot/udev/UART/service evidence and replacement-Pi recovery for recovery requirements. The active aliases in captured evidence are /dev/arduino_gantry → /dev/ttyUSB1 and /dev/arduino_hydroponic → /dev/ttyUSB0; the arm uses /dev/ttyAMA1. They must be reverified on a replacement machine. Do not redirect the arm to the absent /dev/arduino_roboticarm alias.

The refactored app.py without --simulate is hardware mode. This handover does not promote it to the legacy entry point or authorize launching it.
